# ค้นหาโพสต์ที่กล่าวถึง SiPH ด้วย Google Alerts

ระบบอ่าน RSS/Atom ของ Google Alerts ที่เจ้าของบัญชีสร้างเอง ไม่มีค่า API สำหรับตัวนำเข้านี้ แต่ Workers/D1 และผู้ส่ง Email/LINE ยังขึ้นกับโควตาบัญชี ไม่ต้องให้รหัสผ่าน Google แก่ระบบ

Google พบได้เฉพาะหน้าสาธารณะที่ทำดัชนีไว้ โพสต์ส่วนตัว กลุ่มปิด และหลายหน้าบนโซเชียลอาจไม่ปรากฏ ผลที่ได้อาจมีข่าวหรือโพสต์ของโรงพยาบาลด้วย ไม่ใช่ Social Listening API ของแพลตฟอร์มและไม่รับประกันครบทุกโพสต์

## 1. สร้าง Alert ในบัญชี Google ของคุณ

เปิด https://www.google.com/alerts และเข้าสู่ระบบเอง เริ่มจากคำค้นแยกแพลตฟอร์ม เช่น:

```text
("ศิริราช ปิยมหาราชการุณย์" OR "ศิริราชปิยมหาราชการุณย์" OR "SiPH") site:facebook.com
("ศิริราช ปิยมหาราชการุณย์" OR "ศิริราชปิยมหาราชการุณย์" OR "SiPH") site:instagram.com
("ศิริราช ปิยมหาราชการุณย์" OR "ศิริราชปิยมหาราชการุณย์" OR "SiPH") site:tiktok.com
("ศิริราช ปิยมหาราชการุณย์" OR "ศิริราชปิยมหาราชการุณย์" OR "SiPH") (site:x.com OR site:twitter.com)
("ศิริราช ปิยมหาราชการุณย์" OR "ศิริราชปิยมหาราชการุณย์" OR "SiPH") site:pantip.com
```

Dashboard มีลิงก์เปิด Google Search ด้วยคำค้นจาก 4 คำแรกในการตั้งค่า ใช้ตรวจผลและคัดลอกไปสร้าง Alert เอง การเปิดลิงก์ไม่ได้สร้าง Alert อัตโนมัติ เพิ่มคำค้นแบบไม่จำกัด site แยกต่างหากได้ถ้าต้องการเว็บอื่น

ใน “แสดงตัวเลือก / Show options” เลือกแหล่ง Web หรือ Automatic ตามผลตัวอย่าง ภาษาหรือภูมิภาคที่ต้องการ และผลลัพธ์ทั้งหมดหากมีตัวเลือก ตรวจตัวอย่างผลก่อนบันทึก คำว่า SiPh อาจหมายถึงเทคโนโลยี ตัวนำเข้าจึงกรองบริบทโรงพยาบาลเพิ่ม

ที่ “ส่งไปยัง / Deliver to” เลือก **RSS feed หากบัญชีมีตัวเลือกนี้** แล้วสร้าง Alert คัดลอกลิงก์จากไอคอน RSS โดยไม่เผยแพร่ หากมีเฉพาะอีเมล ให้หยุดขั้นตอนเชื่อม feed และแจ้งผู้ดูแลว่าบัญชีไม่มี RSS ตัวนำเข้าไม่สามารถใช้อีเมลหรือหน้า Google Search แทน URL feed ได้

การสร้าง Alert ไม่รับประกันว่าจะส่งผลย้อนหลังหรือมีผลทันที Google เป็นผู้ควบคุมความถี่และความครอบคลุม ตัวเลือก “as-it-happens” ไม่ได้ทำให้พบทุกโพสต์

## 2. เก็บ feed ใน Cloudflare Secret

ไป Cloudflare → Workers & Pages → `siph-monitor` → Settings → Variables and Secrets → Add → เลือกชนิด **Secret** ชื่อ `GOOGLE_ALERTS_FEEDS` ค่าเป็น JSON array ของลิงก์จริง เช่นรูปแบบด้านล่าง (ตัวอย่างใช้แทนของจริงไม่ได้):

```json
["https://www.google.com/alerts/feeds/ACCOUNT_ID/FEED_ID"]
```

ใส่ได้สูงสุด 10 feeds ใน array เดียว บันทึก/Deploy การเปลี่ยน Secret ตามหน้าจอ Cloudflare ห้ามใช้ชนิด Text ที่มองเห็นค่าได้ ห้ามนำ URL จริงไปใส่ GitHub, issue, screenshot หรือแชต ลิงก์ feed เป็นข้อมูลส่วนตัว แม้ไม่มี API key

ตัวนำเข้ารับเฉพาะ HTTPS บน `google.com` หรือ `www.google.com` ที่เป็นเส้นทาง `/alerts/feeds/.../...` ไม่มี query หรือ fragment ค่า JSON ผิดหรือมี URL ผิดแม้รายการเดียวจะไม่เรียก feed ใดเลย แก้ทั้งหมดแล้วลองใหม่ ระบบไม่เปิดเผย URL ใน Dashboard หรือข้อความผิดพลาดของ feed

## 3. ทดสอบและตัดบัญชีโรงพยาบาลออก

เข้าสู่ Dashboard เปิด “นำเข้าผล Google Alerts เมื่อมี feed” และบันทึก ตั้งค่า “URL ที่ตัดออก” ด้วย URL บัญชีจริงของโรงพยาบาลทีละบรรทัด เช่นบัญชี Facebook/Instagram ที่องค์กรตรวจสอบแล้ว หลีกเลี่ยง URL ย่อหรือ URL ที่มี tracking

กฎเทียบ hostname เดียวกันหลังตัด `www.`, `m.`, `mobile.`; เทียบ path แบบไม่แยกตัวพิมพ์และต้องตรงทั้งส่วน เช่น `/Official` ตัด `/Official/posts/123` แต่ไม่ตัด `/OfficialFan` หาก rule มี query ผลต้องมีคู่ key/value นั้นตรงกันด้วย URL รากตัดทั้ง host จึงควรใช้เฉพาะโดเมนของโรงพยาบาล ไม่ใช้ราก facebook.com เพื่อแทนบัญชีเดียว ไม่มีการขยายไป subdomain อื่นหรือวิเคราะห์เจ้าของบัญชีจากชื่อ

กด “ตรวจข่าว” และดูประวัติรอบตรวจ สถานะมี feed แสดงว่ารูปแบบ Secret ถูกต้อง ไม่ได้ยืนยันสิทธิ์อ่าน Google จนกว่าจะตรวจจริง รายการที่พบมีแหล่งเช่น `Pantip · Google Alerts` หากไม่มีรายการใหม่ อาจเป็นเพราะ feed ว่าง ผลซ้ำ ถูกกรอง หรือ Google ยังไม่พบข้อมูล ดูข้อผิดพลาดแยกตามหมายเลข feed

URL ที่ตัดออกมีผลกับรายการใหม่ทุกแหล่ง ไม่ลบข่าวหรือคิวเดิม การเปลี่ยนคำค้นใน Dashboard ไม่เปลี่ยน Google Alerts ที่สร้างไว้ ต้องแก้ใน Google ด้วย

## การประมวลผลและข้อจำกัด

ตรวจ feed ตามตารางเดิม ชั่วโมงละครั้งในเวลาราชการและทุก 4 ชั่วโมงนอกเวลา ไม่มีการเรียก Google Search อัตโนมัติ อ่านพร้อมกันไม่เกิน 3 feeds รับสูงสุด 100 รายการต่อ feed และนำเข้ารวมไม่เกิน 100 รายการไม่ซ้ำต่อรอบ ลิงก์เป้าหมายถูกถอด Google redirect และ tracking ก่อนใช้กันซ้ำข้าม feed; อาจยังซ้ำกับแหล่งอื่นที่มี GUID ต่างกัน

Sentiment ประเมินจากหัวข้อและข้อความย่อที่ Google ส่ง พร้อมหมายเหตุในรายการ ไม่ดาวน์โหลดโพสต์เต็มหรือความคิดเห็น ควรอ่านต้นฉบับก่อนสื่อสารองค์กร การแจ้งเตือนใช้คิวและการตั้งค่า Email/LINE เดิม ต้องมี Secrets ของผู้ส่งและเปิดผู้รับก่อนจึงส่งได้

ขณะส่งมอบโค้ด ยังไม่มี feed จริงจากเจ้าของบัญชี การทดสอบใช้ feed จำลองและ Workers runtime ในเครื่อง ต้องตรวจ feed จริงหลังตั้ง Secret จึงยืนยันการเชื่อมต่อได้
